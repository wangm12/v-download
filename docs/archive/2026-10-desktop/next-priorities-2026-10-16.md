# 当前版本增量总结与剩余功能优先级

> 历史记录，已归档。本文保留当时的基线、观察和验收范围；当前桌面状态见 [DESKTOP_STATUS](../../DESKTOP_STATUS.md)，网页版执行计划见 [web-download](../../plans/web-download.md)。旧优先级建议不自动成为当前待办。

日期：2026-10-16。基准为本机 **1.1.7 / build 1.1.10 / arm64**，安装运行时哈希仍与最终验收包一致。对照 [Downie 原研究](downie-comparison-2026-10-15.md)、后续实现记录和当前源码；没有重新查询 Downie 新版本，也没有进行新的性能或全站运行测试。本文件是建议，不表示下列功能已实现或已排期。

**建议下一批做 N1「任务实际下载环境诊断」和 N2「原任务内精确格式重选与捕获状态收尾」；再下一批做 N3「外置字幕」。** 当前已能选、下载、发现资源及恢复普通任务，这一顺序优先解决上次安装版实测确认的环境差异和原任务恢复缺口。

## 1. 这几批实际新增和修复了什么

| 方面 | 当前交付 | 边界 |
|---|---|---|
| 精确选择 | 普通来源可锁定 provider 格式 ID，分离视频可配伴随音频；策略支持画质上限、来源编码、FPS 上限、HDR/SDR、音轨语言、视频/音频目标及输出选项。 | 未知事实不冒充满足限制；不能匹配时明确失败。来源编码限制和后续 H.264 转换分开验证。 |
| 可保存方案 | 新建、更新、重命名、删除、设默认；单条、合集/创作者列表和扩展使用同一选择逻辑。内建原画归档、兼容 MP4、音频方案。 | 精确来源 ID 只适用于其 URL，不存入通用预设；公开 Remote API/MCP 方案管理尚未贯通。 |
| 下载意图保留 | 入队冻结方案内容、名称/版本、命名与输出目录；变更默认或删除原方案不重写旧任务。去重纳入输出意图和来源上下文；合集保留原始 entryIndex。 | 这不等于完整多链接批次管理或可配置历史去重策略。 |
| 输出正确性 | 修复 360p 实际下载高画质、已有内嵌字幕丢失；保留适用容器的字幕与章节，执行选择后核验，代表样本完整解码。兼容转换与 MP3 输出已有端到端验证。 | 仍未提供外置字幕下载、字幕语言预设或任意格式自动无损转换。 |
| 扩展数据正确性 | 保留原始媒体 URL、完整 Referer、顶层页面/请求文档上下文；重复观测不重复加分；独立候选不因排名隐藏。 | 分数是启发式排序，不是成功率或已验证质量。 |
| 早期捕获与配对 | document_start 捕获和 ResourceTiming 补报；文档/导航身份校验；修复方案列表鉴权，保留 Origin、扩展身份和 capability 的权限边界。 | 无法恢复从未观测的响应头或任意历史资源。 |
| 候选详情与识别 | 扩展与任务详情可按需读真实媒体事实：编码、尺寸、FPS、音频、字幕流、语言和时长；读取 HLS 声明的变体与外置音频/字幕关系。 | 识别不等于下载字幕；DASH Representation 层级未解析，探测取决于引擎对样本的能力。 |
| 原任务恢复 | 失败/暂停/中断/取消任务可打开 Chrome，明确确认一个替换源，继续原 ID、原方案、原目录；源 URL 与原请求 URL 分别保留。新源使用独立 staging，取消与迟到请求有校验。 | 跨 URL 的 exact 格式仍拒绝替换；这是当前 N2 要补的入口。重新下载不承诺字节续传。 |
| 状态、错误与详情 | 修复 MP3 状态错位、完成前目录提示、404 误判引擎缺失；403 为访问拒绝，明确 401/登录要求才判认证；恢复横幅不再重试历史失败任务；详情按任务 ID 隔离状态。 | R4/R5 原建议的完整阶段错误、统一重试预算与逐引擎续传能力尚未全部交付。 |
| 本机交付 | 最新签名 DMG、Applications 安装、Chrome 重载实测；保留用户数据，备份与可复查证据。清理独立研究目录前归档报告引用证据。 | 本地开发签名，未公证、未建立正式应用更新 feed 或扩展商店分发。 |

上述是本轮增强。yt-dlp/FFmpeg、Chrome 扩展本身、中文站点 adapter、原生登录入口、引擎更新、HTTP/MCP、菜单/托盘/Dock 等此前已存在，不计作本轮从零新增。

## 3. 剩余功能排序

按目前 Mac + Chrome 本机使用场景排序。估计为一名熟悉仓库的开发者的有效开发日，包含相关端到端验证与自审，属于粗估；外部站点、账号条件、证书与商店等待另计，存在共享工作，不能直接相加。

| 排名 | 功能 | 为什么值得做 | 粗估 |
|---|---|---|---|
| **N1 · 下一批** | **任务实际环境诊断与可审阅失败报告** | 同一 DASH 样本在所选 Homebrew FFprobe 与包内 FFprobe 的结果不同；当前引擎列表有版本/来源，但不能完整回答本任务实际使用了哪个 probe、哪些能力可验证，以及扩展是否与应用兼容。 | 3–5 日 |
| **N2 · 下一批** | **原任务内精确格式重选、捕获状态收尾** | 普通策略任务已可换源恢复；锁定旧 URL 格式 ID 的任务仍须另建任务。过期/被替代会话也主要在提交时反馈。补上现有流程的明确缺口。 | 3–5 日 |
| **N3 · 再下一批** | **外置字幕与字幕语言方案** | 当前修好的是已有字幕保留；用户仍不能选择并下载网页提供的独立字幕。是下一项最明显的新下载能力。 | 5–8 日 |
| **N4 · 近期后续** | **认证来源、最近验证结果与恢复入口** | 登录/Cookie 入口已有；当前 `connected` 由是否存在 Cookie 得出，无法证明指定任务可访问。让用户知道该重新登录、重新捕获还是更换凭据来源。 | 4–7 日 |
| **N5 · 中期** | **阶段错误、后处理独立重试与恢复能力** | 下载完成后的合并/转换失败应优先复用已取得内容；明确 byte resume、重下和只重做后处理，统一重试预算。 | 4–7 日 |

## 4. 下一批的具体边界与验收

### N1：让失败任务直接给出可操作的下载环境信息

**已有基础**：[引擎状态](../../../src/main/engineManager.ts#L39) 已包含 path/source/version/updateState，[偏好设置](../../../src/renderer/src/components/PreferencesPanel.tsx#L1318) 已展示版本、来源、更新按钮和路径。新增工作复用这些 owner，补任务实际执行事实，不另建并行引擎列表。

建议交付：

1. 每次任务/识别尝试记录实际执行的 yt-dlp、FFmpeg、FFprobe 路径/版本/来源及应用 build；没有运行事实的老任务标未知。
2. 显示扩展是否连接、是否完成配对、当前协议能力与应用是否匹配；区分未启动、端口冲突、配对失效、需要重载/升级。
3. 按需运行有限的引擎能力诊断；同时保留输入失败和环境能力未知，不因为某一个 DASH 失败就宣布所有 DASH 不受支持。
4. 报告可在本机预览并由用户导出：任务选择、原始/执行来源、阶段、版本与尝试事实。认证值不导出；签名 URL 等来源材料按明确选项处理，默认不自动提交。
5. 提供对应动作：去设置、重新配对、重载说明，或由用户明确选择包内引擎进行本次探测/任务重试。保留自选引擎偏好。

**模块**：`engineManager`、`ffprobe`/`ffmpegDownload` 的执行路径 owner、`mediaInspection`、任务尝试记录、`localServer`/扩展握手、preload、现有设置/任务详情。

**兼容性**：增加可选事实与能力协商；旧任务保持未知，旧扩展仍可走原下载接口。诊断和导出不携带 capability/Cookie/Authorization，也不扩大访问域或自动上传。

**验收**：同一 DASH 样本分别选择当前系统/包内 probe，展示与实际执行一致的路径和结果；缺引擎/离线/错误能力/旧扩展/失效配对/端口冲突各自给出正确动作；导出前可审阅且不泄露认证值；原任务、方案和引擎偏好不被诊断偷偷改写。

### N2：新来源可在原任务里重新确认精确格式

**当前限制**：[recaptureTask](../../../src/main/downloadManager.ts#L3637) 对 exact 的新 URL 明确拒绝。这是正确的限制；新功能需要用户重新确认新来源的格式，不能把旧 format ID 直接复用到另一个 URL。

建议交付：扩展发现候选 → 主进程解析新 URL → 复用桌面现有格式弹窗确认新 provider ID → 显示来源/格式的变化与仍保留的方案约束 → 继续原任务。保留最初请求快照、原始 URL、任务 ID、目录与命名；新选择属于明确确认的本次执行尝试，有独立版本/来源绑定。候选不可任意修改任务目录或通用方案。

同时把过期、取消、被替代的捕获会话状态前置显示，保留清晰的“回到原任务重新开始”入口；不能只靠本地倒计时假定主进程仍有效。

**模块**：`mediaCapture`、`downloadManager`、来源解析 owner、`FormatDialog`、`CapturedMediaDetails`、扩展绑定与新 IPC/HTTP 确认合同。

**兼容性**：保留原快照不可变；本次执行选择需版本化且限定新来源。旧任务/旧扩展保留既有严格拒绝语义。不能把新来源的 provider ID 保存进可复用方案；重新计算受影响的尝试/输出身份。

**验收**：A/B 来源的 format ID 完全不同，原 exact 任务经过明确重选后原 ID 完成；取消/探测失败/来源再次改变/迟到确认/会话被替代都不修改旧任务；高度/编码/FPS 约束仍核对；目录、命名、原快照和已有用户文件保持一致；新源不拼接旧源 partial。

## 5. 再下一批：字幕与认证分别补齐

**N3 外置字幕**：区分人工/自动字幕，选语言和缺失处理策略，先提供 SRT/VTT sidecar，再在容器支持时嵌入。主文件与字幕的对应关系、重名、取消、重试、发布和删除全部复用 `ownedOutput*`。字幕选项进入共享选择/保存方案/单条/合集/扩展；“未选”“尝试获取”“必须有字幕”须有不同完成条件。旧方案与任务按原行为；新字段和产物列表需要能力/版本兼容，不让旧客户端被新默认值破坏。验收至少含双语、人工/自动、无字幕、单字幕失败、已有内嵌轨道与文件碰撞。

**N4 认证状态**：[当前账号状态](../../../src/main/nativeAuth.ts#L216) 只有 Cookie 数量和保存时间，`connected = cookies.length > 0`。新增任务实际认证来源（原生/文件/选定浏览器 profile/无）、最近针对指定来源的验证时间与结果；区分已保存、未验证、验证成功、失败/需重新获取。验证只证明所测站点/资源在某一时刻可访问；401 与原因未知的 403 保持不同。复用现有登录、Cookie 同步及重新捕获，不自动访问别的个人 profile。
